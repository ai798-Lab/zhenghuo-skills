# 信息结构选型库

这是本 Skill 根据资料研究与当前内容场景整理的工作分类，不是某机构发布的统一编号标准。研究入口见 [资料与依据](research-sources.md)。

## 先写一句“读者问题”

先确定读者要弄清什么，再选图。不要看到三段文字就选择三张卡片，也不要为了画圆而虚构一个闭环。

1. **关系**：归属、条件、并行、交接、先后、包含、交集、二维定位、因果还是数量？
2. **构图**：树、分支、泳道、时间轴、嵌套、重叠圆、矩阵、鱼骨、坐标图还是简单列表？
3. **视觉**：套用已确认的字体、配色、手绘线稿与标题样式。

候选构图内部比较即可。能否准确回答读者问题、能否在最终尺寸读清楚，是选择标准；不要求用户每次确认。

## 选型表

“内置”表示脚本已经实现；“定制”表示需要按真实数据绘制，不能伪称一键模板已支持。

| 读者问题 / 信息关系 | 适合的结构 | 本 Skill 路径 | 易误用之处 |
| --- | --- | --- | --- |
| 有哪些独立要点？ | 清单、卡片组、模块网格 | 内置 cards | 编号会暗示顺序，不必要时不用 |
| 先做什么，后做什么？ | 单向流程、阶梯、路线图 | 内置 steps；阶梯/路线定制 | 六个长步骤不塞一横排 |
| 满足某条件后走哪条路？ | 判断菱形、决策树 | 内置 decision 单判断；多级定制 | 分支必须标条件，不画成全都要做的列表 |
| 谁负责，在哪里交接？ | 泳道、服务蓝图 | 内置 swimlane 顺序交接；并行/蓝图定制 | 每个节点有责任归属；串行不能冒充并行 |
| 哪些同时发生，再怎样汇合？ | 分叉—并行—汇合 | 定制显式节点与连接 | 中间两项不能被一条顺序箭头误串起来 |
| 发生在何时、持续多久？ | 时间轴、甘特、历程 | 内置 timeline 为事件顺序；按时距/时长定制 | 等距事件不代表真实等时长 |
| 结果如何反馈到前面？ | 环形闭环、因果回路 | 内置 cycle；带正负反馈定制 | “最后复盘”并不自动意味着回到起点 |
| 谁属于谁，如何逐层拆解？ | 树、组织结构、分类树 | 内置 tree | 父子归属与时间先后不同 |
| 有哪些层，各层承担什么？ | 分层架构、堆叠层、金字塔 | 内置 layers；等级金字塔定制 | 层级不是数值大小；金字塔宽度不要伪装数量 |
| 大范围包含哪些小范围？ | 嵌套框、同心层、集合包含 | 定制 | 包含不等于并列，不能改成普通卡片 |
| 一个核心主题有哪些侧面？ | 中心辐射、思维导图 | 内置 radial 一层；多层可用 tree/定制 | 分支无先后，不加循环箭头 |
| 多个概念互相怎样影响/关联？ | 带关系词的概念图、网络图 | 定制 | 多父节点不能硬塞进树；连线需说明关系 |
| A 与 B 在相同维度上有何差异？ | 对照表、前后对比、小多图 | 内置 table；compare 仅用于少量独立面板 | 同维度对齐，不先完整读 A 再凭记忆对 B |
| 两个标准交叉后落在哪一类？ | 二维矩阵、四象限 | 内置 matrix | 两条轴必须有名称与方向，不能随意放四块 |
| 哪些条件共同满足？ | Venn 交集、Euler 集合关系 | 内置 venn 两集合；复杂集合定制 | 交集要真存在，圆面积默认不表数量 |
| 如何逐层筛选、收敛？ | 漏斗、筛选路径 | 内置 funnel 定性示意 | 转化率/人数必须有数据；不能拿固定宽度假装比例 |
| 为什么出现这个结果？ | 鱼骨、原因树、因果链 | 定制 | 潜在原因与已证实原因分开；相关不等于因果 |
| 由哪些部件组成、各处做什么？ | 解剖标注、剖面、爆炸图 | 定制 | 位置是信息的一部分，不能只列部件名 |
| 数量、变化、分布和比例如何？ | 数据图：条形、折线、分布、散点等 | 按真实数据专门绘制 | 坐标与几何准确；手绘只修饰，不歪曲值 |
| 一篇长解释如何展开？ | 总览＋细节、问题→机制→结果、分段组合图 | 组合布局 | 先有叙事逻辑，再决定几张图，不强制换花样 |

关系上的区分有具体资料依据：树强调归属，[NN/g 的思维导图与概念图比较](https://www.nngroup.com/articles/cognitive-mind-concept/)解释了为什么跨概念关联不能都画成一棵树；[Lucidchart 的泳道说明](https://app.lucid.co/diagram/swimlane/how-to-create-a-swimlane-diagram)把责任与步骤结合；[ASQ 的鱼骨方法](https://asq.org/quality-resources/fishbone)用于组织可能原因，不能当成因果已被证明。

## 阅读适配不应抹掉关系

- 树：减少单图叶子数或拆分子树，保留上位节点与父子关系。
- 矩阵：保留四象限和轴。长解释移至图下对应说明，不能摊成四条独立清单。
- 泳道：保留责任列。手机最多两条长文泳道；更多角色可拆局部交接图并给全局索引。
- 概念网络：先给主干，再给局部；不要让边交叉形成线团。
- 集合图：保持相交/包含关系，解释太长移到图例；不往狭窄交集里缩小字号塞文字。
- 数据图：按显示宽度减少标签密度、使用小多图；不删掉不利于结论的数据。

## 三个结构验收问题

1. 只看形状和连接，读者能否判断出正文的关系？
2. 这张图是否额外暗示了正文没有的先后、因果、比例、等级或循环？
3. 若把所有图标和颜色去掉，结构是否仍有解释作用？

同一批次若反复出现“标题＋等宽卡片”，先复核语义是否真的相同。相同关系保持一致有益；不同关系应换结构。不要为了多样性机械规定每张必须不同。
